What is NOT the contribution (be honest)

Fusion (FastTurn, JAL-Turn), the Pareto operating curve (eot-bench), "beating LiveKit", and "better on French" — all taken or incremental. Don't pitch these. The field moved this month; the honest move is to scope the contribution precisely.

Our contribution · three things

Not a new SOTA method — an applied + principled + resource contribution:

  • Calibrated, cost-sensitive optimal stopping. Others sweep a threshold and never calibrate. We derive the stop from an explicit interruption-vs-latency cost over a calibrated fused (acoustic + lexical) probability — a principled operating point instead of an empirical one.
  • A French medical-telephony EOU benchmark, from real production calls. eot-bench is generic/multilingual; ours exposes the dictation failure modes (spelling, numbers, dates) generic models miss. A resource + domain analysis.
  • Weak-supervision auto-labelling from production (resume-after-pause) — a scalable way to build EOU datasets with no manual annotation.
Evaluation — one harness, two datasets. eot-bench (Apache-2.0 + CC-BY-4.0) = the standard, comparable, French subset runnable now; our gold FR-medical set = same schema, same Pareto metrics (latency vs false-cutoff). The LiveKit model is license-restricted → we cite their published numbers, we don't run their weights.

The gold dataset — captured in prod

Rather than synthetic data, we instrumented the production voice pipeline to log, per call, exactly the signals the model needs — auto-labelled, at real volume, in real inference conditions. Each field earns its place:

  • asr_partials — the recognizing trajectory (lexical). The stream of interim ASR hypotheses (bonjour → bonjour j'aimerais → …). Real incomplete→complete sequences — every partial is a natural "not-done" example, the final a "done". Richer than synthetic truncation, and it matches what the model sees live.
  • caller_text — caller-only, raw ASR (lexical). The patient's words only — no agent echo. Clean, unformatted, exactly the inference input.
  • audio_ref + timestamps — recording + pause/decision/reply (acoustic, decision). The recording pointer + per-turn timing. Unlocks the acoustic branch (Smart Turn on the audio), the true end-of-turn & latency (from the waveform), and calibration.
  • outcome — resume-after-pause · was_interrupted (labels). Did the caller continue after the pause? Was the agent cut off? These raw signals auto-derive the fini / pas_fini label + false-cut — no manual annotation.
  • segmentation_timeout · interrupt counts — current system behaviour (baseline). What the live VAD-timeout system decided — our incumbent baseline to beat.
  • hardcase_tag — spelling / number / date (eval). Auto-tags the hard cases → per-category hold-rate (the exact failures we target).

One model that does everything — or separate pipelines?

A single end-to-end model that ingests audio+text and outputs the decision is tempting. But "specialised model" spans three levels, and the level matters.

  • LEVEL 1 · Late fusion — Two off-the-shelf / fine-tuned models (Smart Turn + CamemBERT), fused by rule/logistic on their scores. current · cheap · interpretable
  • LEVEL 2 · Learned joint head — A small head trained on our labels over the two frozen encoders' embeddings. Only the head learns. the experiment to run
  • LEVEL 3 · Full end-to-end joint — Train both encoders jointly — this is exactly FastTurn / JAL-Turn. future work, not now

Key insight

Our novelty is in the decision layer (optimal stopping + calibration), orthogonal to the representation. Whatever produces the probability — late fusion, a joint head, or a full joint model — the calibrated cost-sensitive decision sits on top. A monolithic model doesn't add novelty; it just competes with the SOTA on their turf.

  • Level 3 = SOTA turf — a from-scratch joint model re-does FastTurn/JAL-Turn with far less data → less novel, not more.
  • Data-hungry & timeline risk — end-to-end joint needs thousands of aligned examples + GPU; we have 4 weeks for methodology + eval.
  • Modular wins operationally — each branch swappable & independently improvable, interpretable, runs on CPU without an LLM (our efficiency angle).
  • Level 2 is the real test — "does a specialised model beat late fusion?" as the learned-fusion ablation, feasible with limited data, without touching the novelty.
  • The data pipeline enables Level 3 later — it accumulates exactly the aligned, labelled examples a future joint model would need.

First result · semantic baseline (text-only)

Lexical fini/pas_fini dataset from 549 historical calls · 2 571 caller turns; first baseline on held-out calls — no audio needed:

FR heuristic veto (floor)62.9%70.9%65.0%9.0%
TF-IDF + LogReg81.1%81.8%23.1%14.7%

Clean progression 63% → 81% → 89% accuracy; the fine-tuned model cuts the interruption rate 65% → 12%.

Limitations · we likely overfit — read 89% as a signal, not the number

  • Train/val divergence — training loss keeps falling (0.33 → 0.22) but validation loss bottoms at epoch 2 then rises (0.334 → 0.354): a mild overfit. Best-epoch is kept, but the margin is thin.
  • Length shortcut — prefixes are systematically shorter than full turns, so the model can partly cheat on "short = not done" instead of learning semantics. Needs length-controlled negatives + eval.
  • Narrow data — ~550 calls, single domain → the held-out score is in-distribution and optimistic; cross-domain / real conditions would drop it.
  • Weak, circular labels — labels = where the current system ended the turn, so the model partly learns to predict that system, not ground-truth completeness.

The truer, harder evaluation comes from the gold audio labels (accumulating) + regularization + harder negatives. We expect the real number to be lower — and that's fine: this is a first signal that the lexical signal is learnable.
